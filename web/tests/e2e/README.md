# SPEED CLUB QA harness

Spec: `docs/07_QA_AND_RELEASE.md`. Commands run from the repo root; the server must be running and `web/public/app` exported.

| Purpose | Command |
|---|---|
| Flows, accessibility, DOM audit and harness self-tests (Chromium + WebKit) | `npm --prefix web run e2e` |
| Module screenshots | `npm --prefix web run visual -- --tier=module --routes=GAR-01,GAR-02` |
| Phase screenshots (background, log in `docs/reports/logs/`): every route of phases 1 to N, into `phase-N/` | `npm --prefix web run visual -- --tier=phase --phase=2` |
| Phase 4 screenshots (devices, sets, `--plan`, `--capture-only`: see below) | `npm --prefix web run visual -- --tier=p4` |
| Resume an interrupted run | add `--resume` |
| Accept screenshots as baselines (after design-QA approval) | add `--update-baselines` |
| Promote the exact reviewed PNGs of a run as baselines (approval JSON per route/cell; dry run unless `--write`; host-dependent routes only from a run on `SPEEDCLUB_BASELINE_URL`) | `node web/tests/e2e/visual/promote-baselines.mjs --approval=FILE.json [--write]` |
| Failure guards (never loosened checks): an attempt over `--cell-timeout` (default 120 s, after its rate-limit room) fails with the step it was in and gets a new browser; no cell finished for `--idle-timeout` (default 10 min) aborts the run with every worker's cell and step | defaults on; progress every 10 cells, a heartbeat every minute |
| Fail on High only, while iterating locally (gates always use the default, which also fails on Medium) | add `--fail-on=high` |
| Lighthouse | `npm --prefix web run lhci` |
| Type-check the harness | `npx --prefix web tsc -p web/tests/e2e/tsconfig.json` |

Results: `docs/reports/visual/phase-N/` holds `<name>.png`, `<name>.audit.json`, `contact/<ROUTE-ID>.png`, `diff/<name>.png`, `summary.json`.

Public pages also go on the two phones: they are what a scanned QR code opens, and EN12's public page needs its DE cell at 393.

**Cells.** Carbon and Hell on every cell, Schwarz in addition on flagship screens. DE everywhere, EN (Carbon) only for EN12 at `iphone15pro` and `desktop1440`. 200 % text (`qaFontScale=2`, the existing override) for flagship screens and forms at `iphone15pro` and `desktop1440`. A route's forced states once at the primary cell, `iphone15pro` Carbon DE. Admin routes keep ADR-212: `desktop1280` and `desktop1440`, Carbon and Hell, the zoom cell `__zoom2` at `desktop1280`, their states at `desktop1280` Carbon DE; public pages keep their `page` capture. When a route's `viewports` exclude its primary device, its states go to the first device it allows (`desktop1280` for a desktop-only member route), never dropped. A route's `viewports` keeps the desktops it lists, the phones for a width below 600 and the tablet for one from 600 to 1199. Every cell runs with `reducedMotion: 'reduce'` and `qaMotion=off`, so the pictures are deterministic.

**Sets** (`visual/p4-sets.mjs`, extended by later modules): FLAGSHIP = the ★ screens of 09 §7 and §9 (WEB-03 Landing and WEB-01 the public vehicle page, the pages a scanned sticker opens) and their registry variants (`<ID>-…`); FORMS = member routes on an auth, wizard, garage-editor, profile-editor or settings path whose states are the editor set (`loading`, nothing `empty`), plus AUTH-11, WEB-05, WEB-09, WEB-10; EN12; TABLET. Every p4 run prints the sets and the ids that are **not built yet** (AUTH-01, ONB-01…03, EVT-02, BIZ-01 at M4.0).

**Names and folders.** `<ROUTE-ID>__<w>x<h>__<theme>__<locale>__<device>[__fs2][__zoom2][__<state>]`, e.g. `HOME-01__393x852__carbon__de__iphone15pro`: the device makes every p4 name distinct from a module or phase name. Output into `docs/reports/visual/p4/` (or `--out`), flat, with one `summary.json` and `contact/`. Baselines in `tests/e2e/__screenshots__/p4/`; a cell without one reports `new` ("no baseline") and does not fail on that alone. `promote-baselines.mjs` sends p4 cells (named with a device) there and every other cell where it always went.

**Audits.** DOM audit, runtime checks, the qa-override contract and the state check run on every p4 cell unchanged. `--capture-only` keeps all of them and their findings, but they do not fail the run (capture failures, baseline mismatches and a changed export still do); `summary.json` then lists every finding (`findings`, `findingsByCheck`, `auditWouldFail`): the documented "before" state the 2.0 redesign must fix. It never relaxes **picture integrity**: a cell with `qa-override` (the page did not apply the requested theme, locale, font scale or state), `state-not-rendered`, `server-error`, `runtime-error` or `broken-image` is no valid picture of its cell, so these fail the run with `--capture-only` too; the run prints them under `PICTURE INTEGRITY` and `summary.json` lists them in `integrityFailures`. Third parties are unreachable on both engines without request interception: Chromium by its host resolver rules, WebKit through a proxy on the discard port that refuses them; either way they are recorded as High `third-party-request`.

## Adding a route

Add one entry to `visual/routes.mjs`. Fields are documented at the top of that file. `ready` must select an element only the real screen renders, usually `[data-testid="<ROUTE-ID>.root"]`. Then add a flow to `flows/` and run the module tier.

## What the app must provide

**Overrides.** With `EXPO_PUBLIC_APP_ENV` other than `production`, the app shell reads `qaTheme`, `qaLocale`, `qaFontScale`, `qaState`, `qaMotion`, `qaNow` from the URL.

**Override report.** While they are active, `<html>` states what was applied. The runner compares every cell, and a mismatch is a High finding, so the matrix can never photograph the wrong theme unnoticed. Blade and admin pages need this too, outside production.

```html
<html data-qa-theme="carbon" data-qa-locale="de" data-qa-font-scale="1" data-qa-state="default" data-qa-motion="off">
```

`data-qa-font-scale` is `"1"` or `"2"`; `data-qa-state` is `"default"` when no state is forced.

**Test IDs.** `testID="<ROUTE-ID>.<element>"`, and `<ROUTE-ID>.root` on each screen root.

**Accessibility.** `role` + `aria-*` (ADR-105). `role="tab"` elements sit in a `role="tablist"` parent. `ActivityIndicator` gets an `aria-label`.

**Touch targets below 44.** React Native Web ignores `hitSlop`. Sizes below 44 (`button.s`, chip, segmented, stepper, checkbox, switch) need a real hit area, one of:

- an invisible absolutely positioned child of the `Pressable` that reaches 44, which also works for the user
- `dataSet={{ qaHitWrapper: 'true' }}` on a wrapper that handles the press and contains exactly this one control

**Truncation.** `numberOfLines` needs the full text as `aria-label` on the same `Text`. The `Text` primitive should do this by itself.

**Exemptions.** `dataSet={{ qaExempt: '…' }}` with `photo`, `qr`, `safe-area` or `hairline`; three more only where they belong: `brand-position` (AUTH-02's logo), `fixed-glyph` (an avatar's initials) and `tab-label` (a tab-bar label in a 72 px cell, capped at 1.15 by ADR-145). Meanings are at the top of `support/dom-audit.mjs`. Other values, or a restricted one elsewhere, are reported as violations; every use is counted in the report.

Seeded ids that change with every seed go into a path as tokens, `/app/garage/{r34}`; the runner reads them once per run (`support/garage.mjs` `demoIds`). A page that answers a 4xx by design names it in `expectStatus` (WEB-06: 410, 404); any other status of 400 and up fails the cell.

## Admin (M3.1)

**CSRF cookie limit (SEC-P1-53).** `GET /sanctum/csrf-cookie` is limited per client address (30 a minute, `::1` counts as `::/64`), and every browser context of a run is a new client from this machine. A 429 of it clears that limiter only (`backend.php reset-csrf-limit`, also part of `reset-limits`) and the request goes once more: in `support/auth.mjs` for the harness sign-in, and for the pages in the context route of `support/fixtures.ts` (an offline page keeps its failure). A second 429 reaches the test.

**Staff sessions.** `support/staff.mjs` with `support/backend.php` `ensure-staff` / `delete-staff`: fixtures `e2e-<label>@staff.e2e.speedclub.test`, one per role (`owner`, `admin`, `moderator`, `support`, `content-editor`, `analyst`) plus `challenge` (ADM-02), `enrol` (not enrolled, ADM-03) and `signin-chromium` / `signin-webkit` (admins for the UI sign-in of `flows/a0-admin-shell.spec.ts`). Every run gives them a new password and new 160-bit TOTP secrets (`support/totp.mjs`, RFC 6238), held in memory only, enrolled, without `password_proof_required` (ADR-218). A sign-in is the real flow over HTTP (CSRF cookie, `POST /admin/login`, `POST /admin/two-factor-challenge`), once per fixture and run: Playwright signs in every kind in the global setup and hands the cookies to the workers in `SPEEDCLUB_E2E_STAFF_RUN`; the visual runner signs in on first use per process. A 429 from a run in the same minute clears the loopback staff limiter of the fixtures once (`reset-staff-limits`). The teardown (and the runner's exit) removes the fixtures, their approval requests and saved views, nothing else; their audit events stay (the log is append-only). DQ-677: the global setup removes every fixture an aborted run left before it creates its own, and the visual runner creates only the fixtures of the auth kinds (`KIND_LABELS`, `E2E_STAFF_LABELS` of `ensure-staff`, which removes every other fixture), so the team pages it photographs count the same people in every run.

Auth kinds: `staff-guest` (signed out), `staff-owner`, `staff-admin`, `staff-moderator`, `staff-support`, `staff-content`, `staff-analyst`, `staff-challenge` (password accepted, code pending), `staff-enrol` (signed in without TOTP). A spec that confirms a password, signs out or changes credentials signs in a session of its own; the shared ones must stay as they are.

**Matrix (ADR-212).** A route whose path starts with `/admin` gets module tier 1280 Carbon de, 1440 Hell de, 1440 Carbon en; phase tier 1280/1440 × Carbon/Hell × de, 1440 Carbon en and the zoom cell `__zoom2` (the 1280×800 window at a 640×400 CSS viewport); its listed states at 1280 Carbon de in both tiers. No black theme, no phone widths, no font-scale cell. The theme goes in as `?qaTheme=` (the admin's own `sc-admin-theme` is cleared between cells). Plain throttles (`throttle:60,1`) count as one limiter in the rate budget, with the smallest maximum.

**DOM audit.** On `/admin` the target floors are 32×32 for a standalone control and 24×24 inside a table row of at most `layout.adminTableRow` (40); every other rule is the member rule. An element inside a `data-theme` frame below `<body>` (the gallery's Carbon and Hell side by side) is checked against that frame's colour tokens. On every surface (ADR-222), the sr-only pattern (absolute, at most 1×1, clipped by `clip`, `clip-path` or overflow) and its content are a counted exemption (`visually-hidden`) from spacing and touch target; a skip link in that pattern (`a[href^="#"]`) is focused during the audit and must then be visible and meet the floor (32 admin, 44 member), counted as `skip-link-focused`.

**Stage fixtures.** A route whose picture needs data every viewer (or a staff queue) would see names a stage fixture in `fixture` (`support/stage-fixtures.mjs`): `announcement-info` / `announcement-warning` (HOME-01-announcement-*: one announcement published through `ConfigVersions` as the only live one; on removal the version it replaced is live again, no rollback copy), `reconsent` (CONSENT: version 2 of AGB and Datenschutz with re-consent at a fixed time, and consent.fixture who accepted version 1), `support-tickets` (SET-15a/b: support.fixture with two requests at fixed times and ids), `draft-owner` (DQ-674: ADM-28* and ADM-30* as the owner of the seeded drafts sees them: `lend-seeded-drafts` sets only `created_by` of the seeded branding and announcements drafts to the `content-editor` fixture, `restore-seeded-drafts` gives each back to the staff member its first `config.draft_saved` event names, also inside `remove-branding-fixture`, `delete-staff` and `ensure-staff`; `ADM-28-foreign` and `ADM-30-foreign` keep the read-only view; in `a11y/axe-admin.spec.ts` it holds A3's `branding` lock). The Playwright flows never meet them.

**Volatile (ADR-223).** `volatile: true` (ADM-06, ADM-06-moderator, ADM-08, ADM-44, ADM-44-event: the platform's live activity; since M3.2 also ADM-10 and its tab cells, whose activity column and Audit tab list the run's own events, and ADM-43, ADM-43-mine, ADM-43-all with the runs' requests) keeps the DOM audit, axe and design review but never compares or writes a baseline outside the fixture states `loading`, `error` and `empty`; such cells report `baseline: volatile` (`baselineVolatile` in summary.json), and `promote-baselines.mjs` skips them and lists them as skipped. **Specs.** `flows/a0-admin-shell.spec.ts` (Chromium + WebKit): TOTP sign-in, dashboard queues and KPIs, ⌘K, theme + DE/EN across a reload, the analyst's 403 on ADM-44 and a refused direct export, the export behind the password dialog (ADR-215) and its approval on ADM-08, the idle warning with Playwright's fake clock. `a11y/axe-admin.spec.ts` runs axe on every admin route of the registry in Carbon and Hell, its states and the shell's overlays.

## Rules

Never weaken a threshold, skip a test or commit `.only`. Quarantine needs an ADR. Tests use `test` and `expect` from `support/fixtures`, which freezes the clock, blocks third parties and fails on page errors.

After a failed test the fixtures ask the page whether it still renders: a `[render-probe]` line in the run log (and a `render-probe` attachment) reads `"renderingUpdates":"running"` or `"stopped"`. `stopped` with JavaScript still answering is the WebKit-on-Windows stall (RISK-4, microsoft/playwright#43818, closed upstream as "not planned"), not a defect of the app; on the Mac it did not occur (M1.9). The probe only sees a stall that lasts until the test ends; a freeze that ends earlier shows in the trace: `node web/tests/e2e/support/trace-gaps.mjs <test-results/…/trace.zip>` lists the slow steps, the gaps between screencast frames and the slowest requests. A gap of many seconds with the steps standing still and the app's next request leaving late is the freeze; slow requests point at the server instead; neither means anything was "fixed" by a longer timeout or a retry.

Keyboard specs press `Alt+Tab` on WebKit (`tabKey(browserName)`): WebKit on macOS, like Safari without "Press Tab to highlight each item", tabs between form fields and `tabindex` elements only and reaches buttons and links with Option held.

## Running QA commands next to other work
`export:web` replaces `web/public/app`, which invalidates a browser run in progress. Wrap every export, e2e, visual and Lighthouse run so they queue up: `node scripts/dev/qa-run.mjs npm --prefix web run e2e`.

## Showcase crawl (Phase 4)

`crawl/showcase.spec.ts` (config `crawl/crawl.config.ts`, helpers `crawl/lib.ts`, setup and report `crawl/setup.ts`) visits every page a guest, the showcase member and the showcase admin may see, on `iphone15pro` (WebKit 393×852), `desktop1440` (Chromium) and `desktop1440-webkit`, and fails a role × device run on console or page errors, failed requests and 4xx/5xx answers, broken images (also a GET of every image URL found, `og:image` and icons included), empty or error states where the role should see content, visible i18n keys and unfilled `[[…]]`/`{{…}}` placeholders, and QR codes whose `/c/{code}` does not end on its `/v/{slug}` with 200. Ids come from the API as the member (never from the seed); admin pages come from `crawl/admin-routes.json` (`node web/tests/e2e/crawl/admin-routes.mjs` after a change of `routes/admin/*.php`; the `@meta` test checks it locally), records of admin detail routes from links on the crawled admin pages. It needs no database access, so it runs against staging too. Run commands and environment are in the spec's header; always through `scripts/dev/qa-run.mjs`. Report: `docs/reports/phase-4/showcase-crawl-<target>.{md,json}`. Legitimately empty sections are allowlisted per page with a reason (`allowEmpty` in `crawl/lib.ts`); registry routes the crawl does not visit are listed with a reason in `EXCLUDED`.
